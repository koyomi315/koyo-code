# UI Polish Spec

## 背景

KoyoCode 的 TUI 当前存在若干视觉与交互体验问题，整体观感与「类 Claude Code 终端助手」的定位有差距：

1. **顶部 banner 不够精致**：启动时用猫咪 ASCII 加版本/cwd/就绪提示拼成，没有品牌 logo，信息密度与排版较粗糙。
2. **用户 query 与 AI 回复界限模糊**：历史区中用户输入与 AI 回复都用 `●` 前缀标记，滚动回看时难以一眼分辨「这是用户问的」还是「这是 AI 答的」，也难以快速定位某条 query 及其回复。
3. **生成完成后不自动滚到底**：一轮生成完成、最终回复写入历史区后，历史区不会可靠地滚动到底部，最新回复常停留在视口之外，需手动滚动。
4. **无完成提示**：生成完成时除了 一行暗淡耗时外，没有任何主动信号提示用户「回复已就绪」，用户切走看别处时无从得知。
5. **细节粗糙**：流式动态区（Imagining/Running）、工具调用行与结果摘要、配色与符号策略（`●`/`√`/`└` 混用）等细节不够统一干净。

当前实现要点（用于定位改动范围，非需求约束）：

- banner 由启动横幅拼装函数生成：猫咪 ASCII + 版本 + cwd + 就绪提示行，无 logo。
- 历史区：用户消息 `● text`（粗体）、助手消息 青色 `●` + Markdown 回复 + `  √ {elapsed}s`（暗淡）。
- 自动滚动：挂载历史 widget 后调度滚动到底，但 Markdown 回复异步展开，最终回复挂载后滚动时机过早，导致未真正滚到底。
- 完成提示：仅有一行暗淡耗时，无主动完成信号。
- 流式动态区：`Imagining... (Xs · 第 N 轮)` / `● name(args) Running... (Xs)`。
- 工具行：`● name(args)`（粗体青色）；结果摘要 `  └ {body}`（暗淡/红色，截断约 8 行）。
- 状态栏：`● MODE  (shift+tab to cycle)    model  ↑in ↓out tok`。

## 目标

- 重做顶部 banner：去掉猫咪 ASCII，新增左上角品牌 logo--用 3x5 点阵（每字母 3 列 5 行的 1/0 位图）拼出 `KOYOCODE` 字样，鲸鱼蓝（#2496ED）背景色填充像素（每个像素用两个带背景色的空格渲染成近似正方形），字母间留一列空隙。logo 下方为功能性头部--应用名与版本、当前工作目录、按键提示（发送/换行/模式切换/退出）。各信息用配色与排版区分主次，整体克制干净。
- 生成完成后历史区可靠地自动滚动到底部，完整展示最新回复。
- 生成完成时在状态栏闪现「✓ 完成」提示，约 2 秒后恢复常规信息。
- 统一历史区配色与符号标记，让用户输入与 AI 回复有明确可辨的视觉界限，滚动回看能快速定位每条 query 及其回复。
- 优化流式动态区、工具调用行与结果摘要的呈现，降低视觉噪音。
- 轮次之间加分隔，提升多轮对话可读性。

## 功能需求

- F1 (Banner 重做): 启动 banner 去掉猫咪 ASCII，改为「品牌 logo + 功能性头部」：
  - **Logo**：用 3x5 点阵（每字母 3 列 5 行的 1/0 位图）拼出 `KOYOCODE` 字样，鲸鱼蓝（#2496ED）背景色填充像素（每个像素用两个带背景色的空格渲染成近似正方形像素），字母间留一列空隙。Logo 位于头部左上角。
  - **功能性头部**：logo 下方显示应用名与版本、当前工作目录、按键提示（发送/换行/模式切换/退出），用配色与排版区分主次，整体克制干净。
- F2 (自动滚动到底): 一轮生成完成、最终回复写入历史区后，历史区自动滚动到底部，使最新回复完整可见；流式持续输出期间也保持跟随到底部。滚动需保证在回复内容完全展开后生效，不因内容异步展开而停留在中部。
- F3 (完成提示): 生成完成时，状态栏短暂显示「✓ 完成」类完成标记，约 2 秒后自动恢复为常规状态栏内容（模式/model/token）；完成提示期间不丢失常规信息，恢复后状态一致。
- F4 (用户/助手界限): 用户输入与 AI 回复在历史区采用可明确区分的视觉处理（不同的符号/颜色/样式），使滚动回看时能一眼分辨「这是用户问的」与「这是 AI 答的」，并能快速定位每条 query 及其回复。
- F5 (配色与符号统一): 统一历史区各角色（用户/助手/工具/工具结果/错误/耗时/通知）的符号与配色策略，去掉不一致的标记，降低视觉噪音；错误信息保持醒目可辨。
- F6 (流式动态区): 优化生成中的动态区呈现——措辞更克制、计时更简洁、必要时增加动效感（如旋转指示符），避免冗余文字。
- F7 (工具行与结果摘要): 优化工具调用行与结果摘要——长参数折叠/截断、结果缩进与截断表现更清晰，错误结果与正常结果可辨。
- F8 (回合分隔): 多轮对话中，相邻轮次之间有视觉分隔（留白或细分隔线），使每轮「query + 回复」成组、结构清晰。

## 非功能需求

- N1: 改动限于 TUI 呈现与交互层（banner 拼装、历史区渲染、流式动态区、状态栏、自动滚动），不改动 agent loop、权限引擎、provider、工具实现等业务逻辑。
- N2: 配色在终端默认深色主题下清晰可辨，且与现有权限模式配色（ACCEPT_EDITS 琥珀黄 / PLAN 青蓝 / BYPASS 红）不冲突。
- N3: 自动滚动与完成提示不破坏现有选区复制、权限审批交互、模式切换等行为。
- N4: 保持现有 ruff lint、mypy 类型检查与测试通过；新增或改动的行为有对应测试。

## 不做的事

- 不改动 agent loop、权限引擎、mode 对工具/权限的实际生效逻辑、provider 调用、工具实现。
- 不改变现有按键绑定（Enter 发送、Alt+Enter 换行、Shift+Tab 切模式、Ctrl+C/Esc 取消）。
- 不改变选区复制、权限审批菜单的交互方式。
- 不引入新的权限模式、新命令或新工具。
- 不做主题切换或可配置配色（本次只统一一套默认配色）。
- 不重写 TUI 框架（继续基于 Textual）。

## 验收标准

- AC1: 启动后顶部 banner 无猫咪 ASCII，左上角显示鲸鱼蓝（#2496ED）方块点阵拼出的 `KOYOCODE` logo，下方显示应用名+版本、cwd、按键提示，排版克制干净。
- AC2: 一轮生成完成后，历史区自动滚动到底部，最新 AI 回复完整可见，无需手动滚动。
- AC3: 生成完成时状态栏短暂显示「✓ 完成」类完成标记，约 2 秒后恢复常规模式/model/token 信息。
- AC4: 滚动回看历史时，用户输入与 AI 回复可一眼区分（符号/颜色/样式不同），能快速定位每条 query 及其回复。
- AC5: 历史区各角色（用户/助手/工具/结果/错误/耗时）符号与配色一致统一，错误信息醒目可辨。
- AC6: 生成中动态区措辞克制、计时简洁，无冗余文字（对比现状明显更干净）。
- AC7: 工具调用行长参数被折叠/截断，结果摘要缩进与截断清晰，错误结果可辨。
- AC8: 多轮对话中相邻轮次间有可见分隔（留白或细线），每轮成组。
- AC9: ruff、mypy、现有测试通过；改动行为有对应测试。
